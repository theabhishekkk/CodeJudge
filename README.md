# CodeJudge

CodeJudge is a distributed online judge for evaluating code generated by LLMs safely in isolated containers. The platform is designed for research workloads, benchmark runs, and reproducible grading.

## Architecture summary

- FastAPI gateway accepts logins, problem metadata, and submissions.
- RabbitMQ and Celery coordinate asynchronous grading jobs.
- PostgreSQL stores users, problems, test cases, submissions, and run results.
- Redis handles short-lived state and rate limiting.
- Worker processes run code inside fresh sandbox containers using Docker.
- Frontend exposes login, problem detail, submission polling, and dashboard views.

## Quickstart

1. Copy environment variables:
   ```bash
   cp .env.example .env
   ```
2. Start the infrastructure stack:
   ```bash
   docker compose up -d
   ```
3. Run migrations:
   ```bash
   make migrate
   ```
4. Seed the default admin user and sample problems:
   ```bash
   make seed
   ```
5. Start the worker on the host:
   ```bash
   make worker
   ```
6. Open the frontend:
   ```bash
   cd frontend && npm install && npm run dev
   ```

## API examples

Register a user:
```bash
curl -X POST http://localhost:8000/api/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"email":"user@example.com","password":"secret123"}'
```

Submit a solution:
```bash
curl -X POST http://localhost:8000/api/submissions \
  -H 'Authorization: Bearer <token>' \
  -H 'Content-Type: application/json' \
  -d '{"problem_id":1,"language_id":"python3","source_code":"print(sum(map(int, input().split())))"}'
```

Check a submission:
```bash
curl http://localhost:8000/api/submissions/<id> \
  -H 'Authorization: Bearer <token>'
```

## Security model

- Untrusted code is never executed on the API host.
- Sandboxes are short-lived and isolated with Docker hardening.
- Hidden tests are never returned by endpoints or logged.
- Workers use idempotent writes to avoid duplicate run results.

## Research workflow

```bash
python scripts/benchmark.py
python scripts/metrics.py
```

## Limitations

- Timing measurements are best-effort and can vary on shared machines.
- The initial implementation supports only Python 3 and C++17.
- Docker-based sandboxing is the recommended production path; gVisor or Firecracker can be used for a stronger isolation boundary.

## Notes for production

- Keep workers on separate hosts from the API and frontend.
- Use managed Postgres and broker services in production.
- Populate deployment secrets in GitHub Actions or your cloud provider.
